# 音频信号处理 / Audio signal processing

范围：通用生产分析与主机合成实验；Android手机现场精度和端到端延迟待验证。本文与源码共同构成《数据分析与特征提取》课程成果，不将基础算法声称为项目原创。

## 采集、所有权与时间轴

用户主动开始试测音后，Kotlin申请RECORD_AUDIO，Oboe打开单声道float32输入。使用打开流的**实际采样率**，不在应用中重采样；mono/float转换可由Oboe完成。优先请求Unprocessed，失败降级VoiceRecognition；厂商AGC/降噪/回声处理状态始终标为未知。API24–26使用Oboe的OpenSL ES后端，较新系统可用AAudio；没有手机证据时不把编译成功等同于旧系统运行通过。

回调仅将PCM复制到预分配65536样本SPSC队列，使用32位原子索引；不运行FFT、YIN、JNI、文件操作或等待锁。满队列丢弃新样本，不覆盖消费者正在读的数据。后台工作线程遇到丢样或积压超过200ms，清队列、丢弃不连续分析窗并重置跟踪。停止时先关闭音频回调，再结束/join工作线程，最后释放缓冲。控制操作由单一Kotlin executor串行；会话ID防止旧owner停止新流。

80ms窗口，20ms步长：N=round(0.080 fs)，H=round(0.020 fs)，在44.1kHz为3528/882样本，在48kHz为3840/960。搜索约50–2000Hz；低端每窗约4个周期，固定YIN积分窗W=N−ceil(fs/50)−2约60ms、约3周期。80ms采集窗是基本观测成本，不能由UI动画消除。窗末样本计数/fs定义结果时间。软件队列/发布年龄单独传输；不把它当硬件总延迟。

## 预处理

复用模块：`native/include/opentune/features.h`、`native/src/features.cpp`。

每帧去均值：μ=(1/N)Σx[n]，z[n]=x[n]−μ；能量E=Σz[n]²，RMS=sqrt(E/N)，电平=20log10(max(RMS,10⁻⁶)) dBFS。该处理移除恒定直流，但不是连续高通滤波器；80ms内的极低频漂移仍可能残留。保留本阶段频段，不额外堆砌可能偏移相位/延迟的带通滤波。输入必须有限数值；削波比例=数量(|x|≥0.999)/N，超过2%拒绝有效音高，但保留诊断与真实波形。

数值静音门槛−105dBFS，与旧版−60dBFS区别见比较集弱音实验。绝对音量很低并不自动表示不可测；弱音仍需满足周期性和谐波门控。这里不承诺手机能在其实际噪声底以下识别弱音。

噪声底仅由未通过周期/谐波门控的非削波窗口更新，初始未知；F(k)=F(k−1)+(1−exp(−dt/τ))(L(k)−F(k−1))，下降τ=0.2s，上升τ=3s。电平余量L−F只是启发式代理，**不是分离噪声后的真实SNR**，不作为绝对响度拒检阈值。纯音启动前未观察背景时保持未知；非周期语音也可能污染估计。参考 `feature-extraction.md`。

## YIN差分、候选与可靠性

YIN沿用de Cheveigné与Kawahara的周期检测思想[1]。固定W的差分函数：

d(τ)=Σ(j=0..W−1)(z[j]−z[j+τ])²。

d′(0)=1；d′(τ)=d(τ) / ((1/τ)Σ(j=1..τ)d(j))。

代码通过零填充FFT计算完整序列和前W点的互相关，再结合前缀平方和计算**同一固定积分长度的差分**，不是取FFT最大谱峰为F0。FFT至少2N，无循环相关混叠。CMNDF越低说明周期重复越好。

从短周期向长周期找首个d′<0.12的谷；即使超出2000Hz也先搜索，以免把4kHz纯音误认为2kHz。额外最多考察6个d′<0.25的局部谷，最终仍要求周期评分q=clamp(1−d′,0,1)≥0.88、频率49.95–2002Hz、谐波一致性≥0.85。频率略超设计边界是数值容差，并非新增可靠音域。

候选用CMNDF三点抛物线插值；再对原始d(τ)的局部余弦曲率作校正：δ=0.5(d₋−d₊)/(d₋−2d₀+d₊)×tan(ω/2)/(ω/2)，ω≈2π/τ，δ限于±0.5样本。该校正对单正弦的差分模型成立，对复合谐波只是近似，必须分别测试，不能用纯音误差代表复杂信号。

Hann频谱提取强局部峰（至少最大峰幅18%，2号bin至min(Nyquist,8kHz)，最多保留64个最强峰）。在log幅度上插值峰频率；若峰接近候选的整数倍（容差max(1.5Hz,0.4%峰频率)），计入谐波能量。比值为一致峰功率/所保留峰总功率。它用于拒绝明显不一致混音，不选择最大谱峰充当F0，也不能证明单声源。

通过门控的候选评分：0.75q+0.25h−0.025log2(τ/2)，偏向同样可靠的较短周期，不引入可锁住旧八度的连续性奖励。首次可靠周期之后超过1.35倍的更长周期不得用于“救回”被谐波门控拒绝的候选。这是保守八度歧义规则：首轮实验中，10dB噪声使440Hz候选不准，延长周期反而能把同一谱峰解释为220Hz的二次谐波，造成错误八度。该规则可能增加某些真实弱基频的拒检；当前缺失基频集回归通过，不能推广到任意钢琴/复音。

Mauch与Dixon的pYIN[2]研究多阈值候选概率及HMM/Viterbi解码。本项目借鉴候选和时间一致性思想，但**没有实现完整pYIN的概率模型、离线Viterbi或训练校准**；上述权重、限制与实时状态机是本项目可复现的工程组合。评分不是识别正确概率。

## 实时跟踪与显示

代码：`pitch_tracker.h/.cpp`。连续坐标p=log₂(f)（乘1200即cents；减去log₂(A4)仅改变原点）。状态为idle/candidate/tracking/switching/uncertain/lost。

- 初次/大于80c跳变：候选相邻一致性<35c；q≥0.97需2帧，否则3帧确认。确认后直接接受新音高，不缓慢穿过中间错误音符。未确认帧无有效输出。
- 稳态：pₛ←pₛ+(1−exp(−dt/τ))(p−pₛ)，τ=140ms；连续3次同向且残差>12c时改为50ms以跟随滑音。dt来自样本时间，限制1–100ms；倒序或>200ms断续重置。
- 短时拒检：不输出旧Hz为有效音高，内部保留记忆至最后有效帧200ms；到期lost，重新进入候选确认。状态记忆与屏幕有效性不同。

原始候选、稳定跟踪、数字显示、指针四层分离。Flutter每33ms至多请求一个新快照；数字Hz最多每125ms更新，保留1位小数，新音名立即更新；高级信息仍显示原始与跟踪Hz。音名采用±55c迟滞，最近音名和数学nearest cents仍在原生快照中，仪表重新按**当前显示音名**计算cents，避免边界来回切换。它不是指定琴弦目标调音。

指针每次从当前渲染位置作32ms短插值，音名参考坐标变化时不把两套cents串接平滑；动画key固定，不因每个无效结果重建。无效时音名/Hz清空，指针灰显最多保持200ms后回中；灰色中心没有“准确”状态。关闭详情停止波形/频谱传输与绘制，频谱谐波门控计算仍必要。

## 参考音互斥

`ToneSynth`用实际输出采样率的相位累加器合成正弦，峰幅0.15FS，10ms起音、30ms余弦收音，3秒自动释放，手动停止也收音。回调只生成样本，控制线程有界等待收音后close。七种六弦预设、88键ET或已显式应用的相容个体模型目标均按当前目标Hz合成；吉他拨弦近似见reference-synthesis.md。

原生单executor保证输入和输出互斥：播放先停止采集并释放流，采集先停止参考音；页面切换/后台/输出设备变化/音频焦点丢失停止播放。播放后**不自动恢复麦克风**，用户到试测音主动开始，避免尾音被当作外部已调准。GUI显示该策略，播放失败不生成假声音。手机路由与爆音听测仍需真机验证。

## 显示参照与课程实践

大字标明参照音，小字标明实际检测音。显示参照在55–85c区间以60ms确认，达到85c不附加确认；可按会话锁定参照。更换参照时60ms淡出、不可见时更换坐标与音名、80ms淡入；同参照32ms插值。参照锁定不锁住raw/trackedHz。实际手机显示时延仍未测。
